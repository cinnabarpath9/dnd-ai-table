# 53 剧本四要素：DM 要知道“怎么带、往哪带”

> 2026-11-10 用户指出：官方短冒险和 AI 玩家流程都缺少明确目标。  
> 一个能正常跑的剧本，不能只有“规则/时长/人数/说明”，还要让 DM 在每一场都知道方向。
> 本文定义四个字段，并说明它们进谁的提示词、什么不该进。

## 1 四个字段

写在 `adventure.json` 的 `meta` 里，字段名用中文，和现有 `meta` 兼容。

| 字段 | 写给谁看 | 作用 | 反例 |
|---|---|---|---|
| `流程关键词` | DM + 玩家 | 这一局从哪走到哪的节点顺序，3~6 个，用 `→` | “冒险”“探索”“战斗”这种空词 |
| `剧本特色` | DM | 这个剧本和别的剧本不一样的具体东西（地点/物件/敌人/结构） | “一个精彩的冒险” |
| `玩法体感` | DM | 探索/交涉/战斗的比例、资源压力、预计强度 | “很好玩” |
| `剧本目标` | DM + 玩家 | 一句话说清队伍为什么上路、最终要解决什么 | “找到宝藏”（没有对象/代价） |

边界：

- `剧本目标` 是**玩家可见**的长期目标；不要把“谁是内鬼/最终反转”写进去；
- 单场秘密、NPC 真实目的仍放 `brief` / `clues` / `threads`，不要塞进四要素；
- `流程关键词` 可以写成数组，也可以写成 `调查 → 追踪 → 对质` 字符串。

## 2 JSON 写法

```json
{
  "meta": {
    "规则": "SRD 5.2 (2024)",
    "时长": "约 2 小时",
    "人数": "1 真人 + 3 AI",
    "流程关键词": ["酒馆套话", "荒原追踪", "古冢开门", "火灵谈判", "对质"],
    "剧本特色": "红袍法师、火灵守卫、古冢图书馆",
    "玩法体感": "调查/谈判为主，短战斗，资源紧",
    "剧本目标": "追查红袍法师与失踪者，把古冢里的真相带出去"
  }
}
```

## 3 进谁的提示词

| 位置 | 内容 | 备注 |
|---|---|---|
| DM 每场任务说明 | 四要素全量 | `campaign_guide()` 拼在 `dm_hint()` 前；只进 DM |
| AI 玩家探索/战斗 | `队伍目标` + `流程关键词` | `loop.campaign_goal`，玩家可见；不带 DM 秘密 |
| 开局大厅 pitch | 四要素 | 真人/观战 AI 都能看到 |
| C 自建卡 / B DM 提案 | pitch（含四要素） | AI 建卡时知道这个剧本要往哪走 |

实现位置：

- `engine/adventure/model.py`：`campaign_guide()` / `campaign_player_goal()`；
- `engine/adventure/runner.py`：`dm_hint()` 注入四要素；把玩家目标写进 `loop.campaign_goal`；
- `engine/rules/loop.py`：探索与战斗的玩家提示词加「本桌目标」块；
- `engine/state/assembler.py`：块顺序登记 `本桌目标`。

## 4 兼容与验收

- 旧剧本缺四要素仍可跑（不硬校验，避免把已有剧本全卡死）；
- **新剧本/新导入剧本应填**；填了才会进提示词；
- 回归：
  - `t_adventure` D6b：DM 提示词有四要素/目标；
  - `t_adventure` D7b：玩家提示词有队伍目标；
  - 全量回归与 `check_docs` 必须过。

## 5 已有剧本

- 示例剧本《哨塔的拖痕》已填四要素；
- EP1《赤焰之中》（本机 `adventures/imported/`，不入库）已填四要素；
- 以后从小说/酒馆卡/PDF 导入，先在 `meta` 里写这四行，再补场景。没有这四行，DM 只能“演场景”，不知道整局往哪走。
