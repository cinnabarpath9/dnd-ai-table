## 3. 真模型：开一局的前置

### 3.1 座位配置

**当前默认测试基线**：DM、planner、默认 AI 玩家用 `deepseek-v4.1-flash`，`reasoning_effort: low`。
**4 AI 混合测试**（EP1）另配 DS/GLM/Claude/MiniMax；不是日常默认。

**自定义接入点**：`base_url` 填服务商给的地址；`model` 可以直接填接入点 ID。
接入点 ID 是**各账号自己的资源**，每人不同、换账号要换，不要照抄别人的。

- 复制 `tools/seat-config.example.json` 到仓库外；
- `api_key_env` 只写环境变量名，不把 key 写进仓库；
- **Claude 必须 `"temperature": null`**：上游拒绝自定义温度，否则 HTTP 400；
- `reasoning_effort` 不填 / `null` = 不发该字段；
- `--max-calls` 是全桌共享硬闸，建议先 20~40。

示例：

```json
{
  "seats": {
    "dm": {"model": "gemini-3.8-flash", "base_url": "https://api.example.com/v1",
            "api_key_env": "DND_KEY_GEMINI", "reasoning_effort": null},
    "pc:艾尔玛": {"model": "claude-haiku-5-5", "base_url": "https://api.example.com/v1",
                  "api_key_env": "DND_KEY_CLAUDE", "reasoning_effort": "medium",
                  "temperature": null}
  }
}
```

### 3.2 启动

```powershell
python -m engine.demo_web --real --session-zero `
  --ai-count 2 `
  --seat-config <仓库外的配置.json> `
  --max-calls 40 `
  --characters-dir <本机卡库目录>
```

`--ai-count` 是默认 AI 人数；进大厅后仍可改桌规模。

### 3.3 建议的第一局

1. 真人卡：先选卡库已有真人卡，避免建卡环节干扰；
2. 剧本：选 `哨塔的拖痕`（短，适合首轮）；
3. AI 同伴：先试 **C**（每个 AI 一次 JSON），失败会退预生成；
4. 不要同时跑 B 和 C，A/B/C 任一成功后另外两条会禁用；
5. 确认上桌后只跑**第一轮**，不要先跑长局；
6. 记录：
   - 每个 AI 是否成功建卡；
   - 是否有 fallback，原因是什么；
   - 第一轮真实行动的 JSON 是否合法；
   - 是否出现审核拒答/超时；
   - 实际调用次数与耗时（token/账单目前不自动统计）。

## 5. 还没验证 / 已知边界

- **EP1 内容过滤**：6 次 400（含最终 DM），未重试/未降级；
- **EP1 Claude 修复后复跑**：录屏/存档是修复前，不能当 Claude 正常证据；

- **长局**：旧入口的三章长跑不能直接当作新开局路径的证据；
- **AI 自建卡自由度**：名字固定、等级 3、推荐属性、半施法职业不自动配法术；
- **B/C 生成卡不入卡库**；手搓同伴卡（A）才进 `characters/`；
- **AI 人数上限 4（总玩家 5）**；未验 5 AI 以上；
- **换剧本/换桌规模**会重置大厅问答与同伴生成；
- **读屏/真机/Narrator/NVDA** 仍未签；
- **账单/token** 不自动统计；
- 真实模型第一次跑之前，建议先备份卡库与存档目录。
