# 47 剧本导入工具（锻造台）

> **定位（2026-11-08）：辅助工具，够用即可，不排期。** 它现在能帮项目做剧本/夹具，
> 剩下的适配器等主线需要时再做（见 40 §2 的 P2）。随项目一起发，独立运行。
>
> 位置：`tools/forge/`。**先放在项目里，边界按独立工具划**——
> 将来要拆成配套项目，只需要把 `tools/forge` 整个搬走 + 改一行 import。
>
> **版权边界（写死在工具里）**：本项目不内置、不下载、不分发任何第三方剧本。
> 工具只读**用户自己选的文件**，产物写到**用户自己的目录**；素材来源与授权由使用者负责。
> 我们不提供"官方战役本下载"，也不把用户导入的内容回传到任何地方。

## 1. 它解决什么

用户手里有四类"素材"，希望变成本项目能跑的剧本（adventure JSON）：

| # | 素材 | 现状 | 路线 |
|---|---|---|---|
| 1 | 小说 txt（用户自有/已授权） | **粗稿已做**（按章切场 + 原文摘句当局面） | 补简报/线索/伏笔 → 人工或上层模型 |
| 2 | 酒馆角色卡（含世界观的 JSON 卡面 / 世界书） | **已做**（JSON / PNG / 外部世界书） | 卡面 → 开场一场 + 背景线 + NPC；简报/线索仍要作者补 |
| 3 | D&D 战役本 / 剧本杀（PDF、MD、docx） | 未做 | 先转文本（PDF 另配），再按「房间/场景/章」切，套第 1 类的流程 |
| 4 | 用户自造世界观（对话式） | 未做 | **Agent 模式**：按草稿契约逐场产出，边聊边校验（见 §4） |

四类共用一条下游：**草稿 → 校验 → 试跑 → 成品 JSON**。

## 2. 契约：草稿（draft）

草稿就是 adventure JSON 的**宽松版**：允许缺字段，缺的由 `contract.to_adventure()` 补
（id、幕、空表），补不出来的（标题、局面、简报）由 `doctor()` 报出来。

```json
{
  "title": "雾渡的第三声钟",
  "meta": {"players": "4", "hours": "2 小时", "source": "自制",
           "流程关键词": ["渡口复勘", "闸房追踪", "钟楼对质"],
           "剧本特色": "雾渡、钟绳黑蜡、断缆两刀",
           "玩法体感": "调查为主，短战斗；线索靠观察/调查",
           "剧本目标": "查明第三声钟是谁敲的，把真相带回雾渡"},
  "promises": [{"id": "p1", "title": "钟绳上的黑蜡", "summary": "谁碰过就留痕"}],
  "scenes": [{
    "id": "s1", "title": "渡口复勘·天光",
    "situation": "天光刚亮，渡口空着，钟绳上挂着一截黑蜡，缆绳的断口还湿着。",
    "brief": {"present": "布兰仰头看蜡，艾尔玛蹲在缆桩旁",
              "span": "半刻钟", "offstage": "茶棚老周还没出现"},
    "world": {"location": "雾渡口", "date": "1492-09-17", "period": "清晨"},
    "clues": [{"id": "c1", "text": "蜡里混着河沙", "skill": "perception",
               "dc": 12, "source": "老船工说这是盲婆的记号"}],
    "promises": ["p1"], "beat_notes": {"p1": "蜡里混着河沙，说明挂蜡的人下过水"},
    "pays": [], "combat": {"enemies": [["Bandit", 2]], "distance": 30, "rounds": 4}
  }]
}
```

**只认这一份契约**：成品必须过 `engine.adventure.parse_adventure` + `Adventure.validate`，
工具不另写一套"看起来像"的 schema（两套规则一定会漂）。

## 3. 已经能用的

```powershell
python -m tools.forge card    卡.png -o 草稿.json                    # 酒馆卡 → 草稿
python -m tools.forge serve   --port 8790                              # 开本地页面（独立）
python -m tools.forge md       tools\forge\template.md -o 剧本.json   # 模板 → 成品
python -m tools.forge novel    小说.txt -o 粗稿.json                  # 小说 → 粗稿
python -m tools.forge doctor   x.json                                 # 能不能跑
python -m tools.forge playtest x.json --scenes 2                       # 假模型试跑（零花费）
```

`doctor` 的统计会给出 `预计真模型调用 ≈ N 次`（按 M1/M2 实测均值：探索场约 8 次/场、
战斗轮约 6 次/轮），用来在跑之前估预算。

模板见 `tools/forge/template.md`，是一份能直接跑通的样本（2 场 1 战）。

**游戏里的入口**：网页顶栏多了一个「锻造台」按钮，打开 `http://127.0.0.1:8790`。
锻造台是**独立进程**（`python -m tools.forge serve`），游戏服不代它启动、也不读写它的文件。

## 4. 现状与缺口

- 已做：固定模板解析、小说切章粗稿、**酒馆卡（JSON/PNG/外部世界书）**、统一校验/落盘、
  假模型试跑、独立本地页面（上传 → 草稿 → 下载）；`tests/t_forge.py` 20 个用例守着（不进项数统计）；
- 未做：PDF/docx 提取、Agent 模式、独立仓库；HTTP API 已有最小版（`/api/convert`），
  还没有 `/complete`（模型补场）与鉴权；
- 已知限制：小说切章只认「第 X 章 / Chapter N」；不认章的书会按空行分段（粗）；
  PDF 需要先转文本（本机没有内置 PDF 解析，计划用外部转换或让用户给 txt/md）。

## 5. API 与 Agent 模式（规划，未做）

拆成独立工具后，它对外只暴露四个动作（**都不落存用户的原文**）：

```text
POST /forge/extract   {kind: novel|card|campaign|brief, file}  → {draft, notes}
POST /forge/doctor    {draft}                                  → {ok, errors, warnings, stats}
POST /forge/complete  {draft, scene_id}                        → {draft'}   # 模型补一场（用调用方的 key）
POST /forge/playtest  {draft}                                  → {problems}
```

`complete` 就是第 4 类素材的形态：用户说"我要一个雨夜水寨的世界"，Agent 按场景逐场产出，
每场都过 `doctor`，**不合格就不许落盘**（`write_adventure` 已经是这个口径）。

模型用的是**调用方自己的 key**；工具自己不保存、不训练、不回传。

## 6. 判断

**先把"契约 + 校验 + 试跑"做对，再谈抽取。** 理由：四类素材的产物最后都要落到同一份
adventure JSON；抽取层换模型、换算法都会变，契约与校验不会。现在这条已经通了，
剩下三类素材只是"喂给草稿层的方式不同"。

## 7. 参考实现：Novel-Auto-Generator（只借方法，不借代码）

用户给的参考：<https://github.com/CyrilPeng/Novel-Auto-Generator>（SillyTavern 插件，MIT，
192 星，1.10.0）。它做两件事：**自动续写小说** + **TXT 转世界书**（抽取角色/地点/组织，
支持并行、重试、断点续传、增量导出、别名合并）。

对我们有用的四条（这是"抽取层"真正难的地方，不是调一次模型）：

1. **断点续传 + 检查点**：长小说要按章处理，每章落一条进度（哪章做完、抽出几条），
   中断后从断点续；进度文件要和产物放在一起（我们计划叫 forge 状态文件）。
2. **空回 / 过短重试**：模型偶尔只回思考不回正文（我们在 M2 真跑里吃过两次），
   参考实现的做法是"重发当前章、限制重试次数、连续失败就停并提示"，不是静默跳过。
3. **别名合并**：同一人物在不同段落有多个称呼（老周 / 摆渡人 / 周伯），
   抽出来必须合并成一条世界书条目，否则世界书会碎成一堆重复项。
4. **增量导出**：每抽完一章就能导出一版可用的世界书，而不是等整本抽完才给结果。

不借的部分：它的宿主是 SillyTavern（插件挂在聊天页），产物是**世界书**；
我们的宿主是本项目，产物是**adventure JSON（场景/简报/线索/伏笔）**。
所以它的 UI 与存储层不适用，我们只借"分批 + 重试 + 合并 + 断点"这套工程做法。

落地顺序（与 §1 的四类素材对应）：

| 阶段 | 做什么 | 依赖 |
|---|---|---|
| 已完成 | 酒馆卡 + **别名合并**（同 keys 的条目合成一条）+ 候选线索建议（只建议、不落稿） | 无（纯规则） |
| 再下一步 | `complete` 端点：小说按章 → 模型抽场景/线索 → 每章落检查点 → 增量导出 | 调用方 key + 预算 |
| 之后 | PDF/docx 转文本、Agent 对话式自造 | 外部转换 / 预算 |

**为什么现在不做抽取层**：它每次都要花钱，而且抽取质量取决于提示词与素材；
先把"契约 + 校验 + 断点/重试脚手架"做对，抽取层换模型时不用重写下游。

## 8. 别名合并与候选线索（2026-11-08 补）

**别名合并**：卡面里同一个对象常写成「老周 / 摆渡人 / 周伯」三条，不合并世界书会碎。
规则很简单、可回归：`keys` 有交集（或某条的标题出现在另一条的 keys 里）→ 同一条；
合并后标题取最长的 comment，正文去重拼接，别名记在摘要前缀（`别名：渡口、雾渡口 ｜ …`）。

**候选线索**：从合并后的背景线里挑"可被查的痕迹"，**只输出建议、不写进草稿**：

```text
候选线索 1 条（**没写进草稿**，确认后再加）：
  · [investigation DC 14] 盲婆住在下游水寨，用黑蜡在钟绳上做记号，谁碰过第三根钟绳就留痕
```

为什么不写进去：`dc` 是裁定，必须作者定；把世界书全变成线索会让玩家"随便看就全知道"。
触发词只认**痕迹类**（刀痕/字迹/账本/缺页/刻痕/记号/机关/锁/账/名单/蜡/脚印/血迹/痕迹/气味/声音/影子），
地名器物名（雾、钟、灯、绳）不算——否则「雾渡口」会因为一个「雾」字被建议成线索，噪声比信号多。

回归：`tests/t_forge.py` 里 `test_alias_merge` / `test_clue_suggestions` /
`test_suggestions_not_written_into_draft` 三项守着。

## 9. 导入官方免费短冒险（个人游玩；2026-11-09）

**版权边界**：WotC 的正式战役（《Curse of Strahd》《Tomb of Annihilation》等）是付费商品，
**没有合法免费下载**；网上流传的 PDF 不要用。可合法拿到的官方免费内容只有零星几份，
比如 2021 年 *Adventures in the Forgotten Realms* 的五篇免费冒险（EP1《In Scarlet Flames》等，
`media.wizards.com` 官方 PDF）。**下载只留本地、不进仓库**（`.gitignore` 已挡
`adventures/imported/`）。

**做法（以 EP1 为例，实测 15 页 / 44k 字符）**：

1. 从 WotC 官方地址下载 PDF 到 `adventures/imported/`；
2. 用 `pypdf` 抽文本（`pip install pypdf`；本机没装其它 PDF 工具）：
   `python -c "from pypdf import PdfReader; ..."` 或看 `docs/49` 同目录脚本；
3. 按 [DM 结构化设定协议](DM结构化设定协议.md) 与现有 JSON 结构写成 4~6 场：
   幕（acts）/ 线索（skill+DC）/ 伏笔（promises）/ 议程（agenda）/ 地图（places+passages）/
   战斗（SRD 怪物名，按队伍等级缩放）；
4. `python -m tools.forge doctor <json>` —— 必须"可以跑"；
5. `python -m tools.forge playtest <json> --scenes N --players 4` —— 假模型试跑，0 花费；
6. 再跑 `python -m engine.demo_table --adventure <json>` 或 `demo_web` 真玩。

**已做的一份**：`赤焰之中-EP1`（5 场 / 1 战 / 11 线索；8 级原模组按 1~5 级卡缩放），
doctor 通过、假模型 5 场 0 问题。**它只在本机，没进 git。**
