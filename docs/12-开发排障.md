## 1. 真模型调度

### 1.1 当前实现

- `RealModel` 默认 `enabled=False`；不显式打开不发请求。
- **进程闸门**：`DND_NO_REAL_CALLS=1` 时，真客户端在发请求前直接失败（`attempts=0`）；
  假模型不受影响。回归/联调一律先设它；跑真批次前显式取消。
- 当前默认：单次超时 **180s**、整手预算 **300s**、`max_attempts=2`、**无流式**。
- 出口闸 `engine/netguard.py`；回归默认 `DND_NETGUARD=1`；记账由 `ModelClient.complete()` 统一做。
- trace 记录 `cached_tokens`（上游有才记，0 不代表没命中）；`review_trace.py` 按 task 打缓存命中率。
- **建议值不是当前值**：150s 单次 / 540s 整手 / 450s HTTP / 25s 流式空闲 / 4 次客户端重试 + 2 次换家
  （最坏 15 次请求）目前**没有全部落地**，接长跑时再调；不要引用成“现在已这样”。

### 1.2 多模型座位（2026-11-09 接）

`--seat-config` 读一份 JSON，让 DM / planner / 每个 PC / pilot 各走各的模型和 provider：

- 标签：`dm`、`planner`、`pc:艾尔玛`、`pc:罗恩`、`pc:小翠`、`pc:布兰`、`pilot`；没列的 PC 走 `pc:*`。
- 每座位字段：`model`、`base_url`、`api_key_env`（**只写环境变量名，不写 key**）、
  可选 `reasoning_effort` / `max_tokens` / `temperature` / `timeout`。
- `temperature: null` = **请求体里不发送 temperature**；Claude 实测会拒绝自定义温度
  （HTTP 400），必须用 `null`。不填走默认 0.7。
- `reasoning_effort` 不填或 `null` = **不发这个字段**。别把“填了”当成“上游一定按档走”：
  Gemini 3.8 Flash 在中转上会被钉在 high；GLM 的档位可能是摆设；Claude 支持 low/medium/high/max。
- 2026-11-10 测试阶段基线：DM / planner / 两个 AI 全部 `deepseek-v4.1-flash`，`reasoning_effort: low`；
  新剧本的 `meta` 四要素见 [53](53-剧本四要素.md)；旧剧本缺字段仍可跑。
  混搭五模型探针只作历史证据，不作为当前测试配置。
- 示例：`tools/seat-config.example.json`。先复制到仓库外，设好环境变量，再：

```powershell
python -m engine.demo_web --real --seat-config <你的配置.json> --max-calls 80

# 只跑 M2 上章 a1 单场（真模型混合桌探针）
python tools\real_smoke.py --seat-config <你的配置.json> --adventure "adventures\M2测试本-上-钟下的账.json" --only a1 --max-calls 40
```

- `--model` / `--base-url` 仍是没配置座位的全局回退；`--reasoning-effort` 是单模型默认档，
  座位配置里的 `reasoning_effort` 优先。
- 注意：`--max-calls` 是**全桌共享**硬闸，不是每座位；五模型测试先卡 40~80，别一上来跑满。

### 1.3 开局大厅（`--session-zero`，2026-11-09 接）

真桌跑团的开局顺序：**DM 先讲战役 → 定桌（1 真人 + 0~4 AI）→ 真人卡/剧本/同伴 → 审卡与序章问答 → 才进第一场**。

- 启动加 `--session-zero`；不带时保持旧的“直接开局”，避免回归/假模型演练改变节奏。
- 大厅内容：
  - `pitch`：优先读剧本 `meta.pitch` / `meta.序幕`；没写就按标题、规则/时长、第一幕、第一场 `brief.present` 拼；
  - `characters`：本桌实际人数（1~5）的姓名/职业/等级/HP/AC，数值来自状态树，不经模型；
  - 大厅里可问 DM **最多 3 个问题**（`lobby_ask`）：真模型走一次 DM 座位调用，假模型给确定性占位回答；
  回答只限战役/角色/开局，不推进场景、不掷骰、不替玩家决定。
- **审卡**：每张卡显示最高属性；真人卡由 DM 给一句评价（20 夸、17 扎实、16 够用、<16 建议调）。
  只提示，不改数值。
- **队友介绍**：实际存在的 AI 队友各说一句（真模型每座位一次短调用；假模型/失败用预置台词）；
  只进大厅展示与日志，不改数值；三句会拼进启航旁白。
- **序章两问**：动机 → 羁绊，一次只问一个；答案进 `lobby.notes`，不改数值，可跳过；
  确认后这两句会拼进启航旁白（让聊天答案真的进剧情，而不是只躺在表单里）。
  这一步不调模型，是脚本化引导；玩家仍可额外问 DM（3 问上限）。
- **桌规模**：真人固定 1 人，AI 0~4 人，总玩家 1~5；AI 卡可由 A/B/C 生成，未生成时用预生成前 N 个。
  单人桌（1 真人 + 0 AI）也能建、存、读、开局。
- **角色卡库**：`characters/*.json` 存建卡选择（不是派生值），默认目录不进 Git。
  建卡面板可读入/存入/删除；`create_preview` 仍由服务器重算。
- **人生路径**：8 问（`engine/lifepath.py`）→ 建卡 payload；答案只做软权重，
  最终仍走 `create_character` 校验；可在建卡面板继续改。
- **AI 自建卡（C）**：大厅「让 AI 自行建卡」给每个 AI 座位一次短请求，按世界简介/
  合法职业/种族/技能输出 JSON；服务器用 `create_character` 校验，失败/假模型退预生成卡。
  生成结果进本桌卡列；不写角色卡库。
- **DM 提案同伴（B）**：大厅填一句“想要怎样的同伴”，DM 一次返回 1~N 位 JSON；
  服务器校验后重建本桌。假 DM / JSON 不合法 / 建卡失败明确报错，不静默替换。
- **手搓同伴（A）**：建卡面板可选「同伴卡」存入卡库；大厅多选框按 AI 人数挑 N 张，
  服务器读回选择重算后上桌。人数不符/不是同伴卡/重名会明确报错。
- **卡库真人卡**：大厅「使用真人卡」直接换真人座位，保留已有 AI 人数/同伴；
  同伴卡不能当真人卡用，观战模式没有真人座位。
- **本桌剧本**：大厅显示当前剧本名，并可从已校验 `adventures/*.json` 里切换；
  换剧本会重开大厅（保留自定义真人卡；动 `WebSession.adv` 后重建桌）。
- **直接上桌**：可跳过两问/Q&A 直接开局（对应“Just Start”），仍走 `start_game`，不重开桌。
- **启航旁白**：四人确认后先打一句 DM 开场（含“现在，你要做什么？”），再启动 `AdventureRunner`；
  具体场景细节仍由 runner 写。
- **开局记录**：确认上桌时把剧本/审卡/两问/队友介绍写进 `session_zero`，随存档 `extra` 落盘；
  读档后快照仍带，工具栏「开局」面板可看。
- 「调整角色卡」打开建卡面板：只替换真人座位，其余 AI 卡不变；建完回大厅，卡列刷新。
- 按钮「N 人确认上桌」（N 为实际总人数）→ `POST /api/act {"kind":"start_game"}` → 才启动 `AdventureRunner`。
- **这一步不调模型**：避免开局先烧一次调用，也避免模型临时编出和剧本冲突的世界观；要更丰富的介绍就写 `meta.pitch`。
- 回归：`t_modes` 87（大厅停在 lobby、动态人数、0~4 AI、5 人桌、卡库真人/同伴、A/B/C、确认后才 playing、旧模式不受影响）；`t_realmodel` 61（F5 intent 不发 temperature）。
- 真实探针：2026-11-10 开局大厅 8 次请求；B/C 成功，Claude 需 `temperature:null`；
  确认后的第一轮尚未验，见 `docs/52-开局与游玩测试.md`。

## 3. 环境注意（5 条）

1. **先 `cd` 到项目根**；会话间工作目录会重置，能用绝对路径就用绝对路径。
2. PowerShell 跑带中文的 Python 会 GBK 乱码；脚本统一 `sys.stdout.reconfigure(encoding="utf-8")`；
   `.ps1` 只用 ASCII 或带 BOM 的 UTF-8。
3. Python 输出被 `| Select-Object -First N` 截断会以 exit 1 结束（broken pipe），**不是失败**；看完整输出重定向到文件。
4. **别用命令行内联 Python**（引号会被 PowerShell 吃掉）；写成文件再跑。
5. **别用 `Get-Content` 数行数**（PS 5.1 按 GBK 解码会数错）；用 `[System.IO.File]::ReadAllLines($p).Count`。

### 3.1 出口闸的边界

- 主进程和回归子进程都在闸门后（`DND_NETGUARD=1`）；
- **不防 UDP、AF_UNIX、没装闸的子解释器**；这不是内核级沙箱。
- 需要“绝对断网”时必须同时确认启动方式和子进程都装了闸。

## 4. 已踩过的 28 个坑（旧 §12 原表 + 网页/审核，别再踩）

按严重度排。前两条是同一类：**"看起来在正常工作、实际在做错事"**。

| # | 坑 | 真相 |
|---|---|---|
| **1** | **治疗术被当成伤害法术** | `Cure Wounds` 的 desc 写着 "regains ... 2d8"，被"兜底抽骰"的正则抽成 `damage_roll` → **治疗术会去打掉队友的血**（实测：受治疗的角色从 40 掉到 29）。**教训：兜底正则必须限定语境**（desc 里出现 "damage" 才相信） |
| **2** | **`targets` 键缺失被当成"有目标"** | `Option.to_dict()` 在目标为空时**不输出 targets 键**，`o.get("targets")` 是 `None`，被当成"有目标" → 假模型每回合挑一个够不着的攻击，**战斗空转两轮**。**教训：`None` 和 `[]` 都必须算空** |
| **3** | **加值算了两遍** | 初版 `roll_d20(rng, modifier=3)` 把 +3 烤进骰式 `"d20+3"`，`AbilityCheck.total` 又加一遍。修法：`display_modifier` **只用于展示、不参与 total** |
| **4** | **`apply_patch(in_place=True)` 失败不回滚** | 状态停在"既不是改前也不是改后"的中间态，**看起来像成功了**。修法：先存备份，失败就地还原 |
| **5** | **中文武器名查不到 SRD** | 存档写"长剑"、SRD 写"Longsword" → 查不到就**静默跳过** → 角色手里没武器。修法：加中英映射表 + 查不到**明说** + 兜底给武器 |
| **6** | **`pc:X` 对 DM 排他**（口径错） | 见旧交接 §4.3。DM 是主持人，必须知道一切 |
| **7** | **装配器允许手动塞「台账」** | 静默失效，或绕过防全知。修法：**直接报错**并提示用 `Ledger.public/.secret/.private` |
| **8** | **`bonus-action`（带连字符）没进映射表** | SRD 用的是连字符写法 → 所有附赠动作法术被当成普通动作 |
| **9** | **`heal_adds_modifier` 正则收尾过早** | `((?:...)?)` 在 `2d8` 处就满足并收尾 → 治疗永远不加施法属性调整值。修法：用**先行断言**收尾 |
| **10** | **格距用欧氏距离** | `(0,0)` 与 `(10,10)` 欧氏是 14.1 尺，但 D&D 里它们是**斜向相邻（10 尺）**。必须用切比雪夫距离 |
| **11** | **`GameLoop` 只按 id 找单位** | 日常轮传角色名就静默跳过。修法：`find_unit()` **id 和名字都认** |
| **12** | **完成度自查漏跑测试** | runner 一开始只 glob `t_*.py`，`check_isolation.py` **从来没被跑过**。修法：glob 两类 + 开头点名"既不叫 t_ 也不叫 check_ 的 .py" |
| **13** | **法术书里的中文名被静默丢掉** | 卡里写「魔法飞弹」「火球术」，SRD 只有 `Magic Missile` / `Fireball` → `get_spell()` 抛异常，而 `make_hero_unit` 里是 `except: continue` → **角色法术书看起来有东西，实际一条也没装**（和武器那条同类）。修法：加中英法术名映射 + 找不到**写进 `unit.notes` 明说**（回归 L25 钉住） |
| **14** | **先攻只掷裸 d20** | `roll_d20(rng, initiative_bonus)` 的 modifier 只进展示，`r.total` 不含加值 → 所有敏捷加值不参与先攻排序。修法：`r.total + u.initiative_bonus`（回归 A1） |
| **15** | **武器属性字段名读错** | SRD 用 `property.name`（Ammunition/Finesse/Reach），代码读 `property.key` → **所有弓被当成 5 尺近战**、灵巧用力量、长柄少 5 尺。修法：读 `name` 并小写（回归 B1–B9） |
| **16** | **中文属性键在检定里算 0** | `adjudicate` 用英文键查 `unit.abilities`，stat_data 是中文键 → 非熟练技能加值全变 0。修法：统一走 `Unit.mod()` 双语入口（回归 C1–C6） |
| **17** | **多投射物只算一发** | SRD 的 `damage_roll` 是单发（魔法飞弹 1d4+1），描述里的"三发"不在数值字段 → 每次少算三分之二。修法：从描述抽 `projectiles`，升环 +1（回归 E1–E12） |
| **18** | **自源范围法术打全图** | `spell_reach` 对 Self 返回 0，菜单和结算都不筛距离 → 15 尺锥命中 200 尺外。修法：按 `shape_size` 过滤，菜单 + 结算两层（回归 F1–F5） |
| **19** | **施法先扣资源后校验** | 先扣法术位/动作/专注、再查目标；空目标还会抛异常炸轮。修法：全部校验前置，失败不扣（回归 G1–G7） |
| **20** | **被敌人打倒不掷死亡豁免** | 回合循环 `if not u.alive: continue` 把 0 HP 单位直接跳过 → 死亡豁免只在"自己回合被打倒"时触发。修法：濒死单位在自己的回合掷（回归 I1–I2） |
| **21** | **专注检定主体反了** | 用"行动者打出的伤害"判行动者自己的专注，真正受伤者从不检定。修法：伤害结算处对**受伤者**检定（回归 J1–J4） |
| **22** | **回合性标记没人清** | dodge/disengage 写进 `used` 却没人 pop → 一次脱离整局免借机，还会进存档。修法：`reset_turn` 清理（回归 L1） |
| **23** | **动作经济的"再校验"被 `if False` 关掉** | 槽位已用还能再打一次，`spend` 异常被吞。修法：恢复 `can_take` 并在失败时 blocked（回归 O1） |
| **24** | **回环测试偶发 502 / 10053** | 两个原因叠加：① 本机 Windows 系统代理指向 `127.0.0.1:65532` 且**不排除回环**，测试的 127.0.0.1 请求被代理吞成 502；② 服务端拒绝跨站 POST 时**不读请求体就断连接**，客户端还在写 body → `ConnectionAbortedError 10053`。修法：测试与 demo 显式设 `NO_PROXY=127.0.0.1,localhost` / 用无代理 opener；服务端拒绝前先 `_drain_body()` 再回 403。**教训：回环不等于"天然不受环境影响"** |

| **25** | **插入代码吃掉 `async function poll` 的前缀** | 整段页面脚本 `await` 落在非 async 函数里 → **脚本不执行、轮询全停**，页面看着正常（静态测试全绿）。修法：`t_thinking.py` D7 守 `async function poll(){` 字样 |
| **26** | **`applyThink` 插进了别的函数** | 服务端 `thinking` 明明有值、页面就是不显示（插在 `refresh` 里，`poll` 没调）。修法：`t_thinking.py` D8 守"只在 `poll` 里出现一次" |
| **27** | **复盘接口的存档名可被穿越** | 直接拼 `name` 会让路径段穿越到目录外（如 `..` + 文件名）。修法：`engine/review.py::resolve` 只认单段 + `.json` + 目录内；`t_review_web.py` B8 守 |

| **28** | **把"模型拒答"当成剧情写下去** | 上游审核/拒答时，回复文本会被当作 DM 旁白进台账（"抱歉，我不能…"），污染后续上下文。修法：`format_check` 分出 `moderation`；叙事层 `_guard_narration` 重述一次、仍拒就留白；`refused` 进留痕与 `review_save`（见 [48](48-提示词注入与审核拒答.md)） |

> 这 28 条是代码/规则层面的真实事故（1~24 旧交接 §12，25~28 见 [48](48-提示词注入与审核拒答.md) 与 20）；本表保证新入口不会“只看到摘要”。
